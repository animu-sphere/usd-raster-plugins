# Binary Distribution and Licensing

Planned obligations. The dependency set is not final; this document records
what must be verified before the first binary release, and it is updated when a
dependency is pinned.

## Licenses in play

| Component | License | Notes |
| --- | --- | --- |
| `usd-raster-plugins` project code | Apache-2.0 | Matching `usd-pointcloud-plugins` |
| OpenUSD | Apache-2.0 (modified) | Runtime dependency of the authoring library, the plugin, and the converter |
| libtiff | libtiff license (BSD-like) | Permissive; attribution required |
| zlib | zlib license | Pulled in through libtiff Deflate support |
| libgeotiff | X-style / public domain components | Only if selected at Milestone 2 |
| GDAL | MIT / various | Test oracle today; planned optional production backend with driver-specific obligations reviewed before packaging |

No current production target links GDAL. ADR-0009 permits it only in the
optional `usdRasterGdal` backend; an artifact that includes that module must
record the exact GDAL build, enabled drivers, transitive libraries, licenses,
and notices. See [ADR-0009](../adr/0009-gdal-raster-backend.md).

## Link model

```text
UsdRasterGeoTiffFileFormat
    -> usdGeoTiff        (static, project)
    -> usdRasterCore     (static, project)
    -> usdGeoCore        (static, project)
    -> usdRasterTiling   (static, project)
    -> usdRasterAuthoring(static, project)
    -> libtiff           (to be decided: static or shared)
    -> zlib              (through libtiff)
    -> OpenUSD           (shared, provided by the host runtime)

optional usdRasterGdal
   -> GDAL              (private; exact link model decided before packaging)
   -> driver-specific transitive dependencies
```

Whether libtiff is linked statically or shared is decided at Milestone 2 and
recorded here, because it changes the attribution and notice obligations. A
permissive license makes either choice viable, so the decision is driven by
deployment: a statically linked bundle is easier to install into a DCC
environment that already ships its own libraries.

If a copyleft dependency is ever introduced, the link model becomes a licensing
question rather than a packaging one, and it requires its own ADR. None is
currently planned.

## Compliance requirements

Before publishing a binary artifact:

1. `THIRD_PARTY_NOTICES.md` lists every redistributed component, its version,
   its license, and its copyright notice.
2. The full license text of each redistributed component ships inside the
   bundle.
3. The pinned version of every dependency matches what was actually built,
   verified against the package manifest rather than against a comment.
4. No test-only dependency appears in the artifact. When `usdRasterGdal` is
   excluded, GDAL must also be absent. When it is included, the linked GDAL and
   driver dependency set must match the package manifest and SBOM.
5. Test fixtures carry their own provenance. Synthetic fixtures generated by
   the repository script are project-licensed; any fixture derived from real
   geospatial data records its source and license separately, and public-domain
   or open-licensed sources are preferred precisely to avoid this problem.

The fixture rule matters more for raster than for most projects: real DEM and
orthophoto data is often government-published with specific attribution terms,
and it is easy to commit a "small test file" that carries obligations.

## Release artifact layout

```text
raster-geotiff-<version>-<target>.tar.zst
    lib/
    resources/
    docs/
    LICENSE
    THIRD_PARTY_NOTICES.md
    SBOM.json
```

Plus, at the release level:

```text
SHA256SUMS
```

## Verification before publishing

```text
1. VERSION, openstrata.toml, the plugin manifest, the plugin CMake project,
   the tag, and the changelog version all agree
2. every declared hosted CI cell passes
3. package digests are reproducible for an unchanged build
4. the packaged binary links only the declared dependencies
5. notices and SBOM are complete and match the pinned versions
6. the release is assembled as a draft for human review
```

Step 4 is the one that catches an accidental oracle dependency, and it is done
by inspecting the artifact.
